# Update check

Sessions: `2393394e-44d3-4470-9f42-36851f5e27a0`, `ce72c3cb-fa14-4617-bb8f-ccb5f47557d3`

## Decisions

- **The app blocks versions under a minimum, because the App Store can't force an update.** iOS auto-update is each person's own setting. A version under the minimum shows a "Please update" screen that can't be closed, and a version under the latest shows a "New version available" sheet.
- **The minimum version comes from the PostHog flag `minimum-app-version`, as its payload.** It can be changed in the PostHog dashboard with no backend deploy and no app release.
- **Preview and development builds read `minimum-app-version-preview` instead.** All builds share one PostHog project, so a separate flag lets a preview build force an update without touching production.
- **The latest version comes from Apple's lookup API.** It updates by itself after every App Store release, so nobody has to change a value by hand.
- **Apple's lookup runs through React Query (`useQuery`) with `fetch`, not `useQueryConfigured`.** `useQueryConfigured` adds `/v1`, our token and our response format, which Apple doesn't use. React Query retries and loads again when the app comes to the front.
- **Apple's answer gets its type from `useQuery`'s generic, with no `as` cast and no zod check for now.** No other response in the app is checked at runtime, so a change in Apple's answer would go unnoticed, the same as with our backend.
- **The update check stays on in the development build.** The simulator runs the dev build, so the check can be tested there. The dev build's version comes from `package.json`, which is the same as the store's or newer, so it doesn't show the screen or the sheet by itself.
- **The "Please update" screen is `ForcedUpdate`, and the "New version available" sheet is its own component, `UpdateSheet`.** Both read the result from one hook, `useVersionCheck`, so the version check runs in one place.
- **The picture, text and button layout shared by the offline view, `ErrorState` and `ForcedUpdate` becomes one component, `InformationBlock`.** It holds the same content as `InformationModal` without the modal, and covering the whole app stays at each place that uses it. Its text is at most 384 points wide (`max-w-sm`), and the block keeps 16 points on each side (`px-4`), so each sentence of the "Please update" text fits on one line on the iPhone SE.
- **"Later" saves the latest App Store version in `skippedUpdateVersionAtom`, and the sheet stays hidden until Apple shows a newer one.** Closing the sheet any other way, like swiping it down or tapping outside it, counts as "Later" too. "Update" doesn't hide it, so a person who comes back without updating sees it again.
- **`openAppStore` lives in `update-check/utils/app-store.ts`, because both `ForcedUpdate` and `UpdateSheet` use it.**
- **The "Please update" screen sits inside `InternetCheck` and outside `BottomSheetModalProvider`.** It covers an open bottom sheet, and the offline view covers it, because the App Store can't open offline.
- **"Update" opens the App Store with `Linking.openURL`, not `WebBrowser.openBrowserAsync`.** The in-app browser would show Apple's web page instead of the App Store app.
- **When the flag hasn't loaded yet, the check is skipped.** The offline view covers the app while the phone is offline, and PostHog's hook updates when the flags arrive, so the "Please update" screen shows a moment after the app goes online. PostHog saves the flags on the phone, so later launches have the minimum right away.
- **Versions are compared number by number with our own small function, with no new package.** App versions are always plain numbers like `1.3.5`, because `app.config.ts` removes any `v` and `-` part.
- **The App Store id is written once in `lib/consts.ts`, and both App Store links are built from it.**
- **PostHog's folder has one folder per job, `events/` and `feature-flags/`, each with its `types.ts` and its hooks next to it.** This copies `features/taste/share-taste-card/`, which keeps one job's files and hook together, and leaves room for more flags. The type files are named `types.ts`, like `siri/types.ts`. The setup files, `client.ts`, `storage.ts` and `screen-tracker.tsx`, stay at the top.
- **Each payload flag has a check in `isFlagPayload`, in `use-feature-flag-payload.ts`, not in `types.ts`.** The checks are code, not types. Adding a type without its check fails `tsc`. PostHog's hook gives every payload as any JSON, and the app uses no `as` casts, so the check is how TypeScript learns the payload's type. A flag whose payload has the wrong type, like the number `1.3` instead of the text `"1.3"`, gives `undefined`.
- **A flag with variants will get its own list next to the payload list, with its options written once in a `const` list.** The type and the check are both built from that list. It's left out until a flag needs it.
- **The "Please update" screen shows the designer's motion, `assets/lottie/force-update.json`, with the title "Update required".** It follows the Figma redesign, and the motion sits next to the app's other motions.
- **The "New version available" message is a bottom sheet with the same motion.** Both update messages then look like one set. Its title, "Update available", uses the `BottomSheet`'s own `title`, like the app's other sheets.
- **`UpdateSheet` is built like `NotificationsSheet`, with a plain "Later" button and a purple "Update" button side by side.** It follows the sheet's design, and like `NotificationsSheet` it pauses trailers with `allowYTPlayingAtom` while it's open.
- **`UpdateSheet` sits next to `NotificationsSheet`, inside `BottomSheetModalProvider`.** A bottom sheet only opens inside that provider. It is inside `ForcedUpdate` too, which never matters, because the sheet and the "Please update" screen never show together.
- **The `BottomSheet` footer keeps at least 16 points below its buttons.** The iPhone SE has no bottom safe area, so the buttons touched the screen's edge. Phones with a home bar keep their own bottom space, because it's bigger.
- **`UpdateSheet` adds 24 points above and below its `InformationBlock` (`py-6`).** It follows the sheet's design, and the space is set in the sheet, not in the shared block.
